# SPEC-ROUTE | การรับงานตามเส้นทาง (ซาเล้ง) - v2
version: 2.0 | status: Draft v2 | owner: กลุ่ม 2 (แพลตฟอร์มรับซื้อของเก่า) / PO: SH-ซาเล้ง | date: 2026-10-04 | baseline: B1 | supersedes: SPEC-ROUTE v1.0

## 1. Intent
ซาเล้งต้องการเห็นตำแหน่งครัวเรือนที่ต้องการขายขยะรีไซเคิลตามเส้นทาง ในรัศมีไม่เกิน 5 กม. เพื่อวางแผนเดินทางไปรับซื้อขยะได้อย่างสะดวก รวดเร็ว และลดการขับรถเปล่า (REQ-FN-002, EV-003, EV-004, EV-012) ส่วนผู้ขายได้ความสะดวกรวดเร็วและราคากลางที่โปร่งใส (EV-001, SC-01) [16, 29, 39]

## 2. Scope & Non-goals
In Scope (จาก Group2.pdf):
- [SC-01] จับคู่งานนัดหมายรับซื้อขยะรีไซเคิลตามพิกัดและช่วงเวลาที่ตกลงกัน [29]
- [SC-02] แสดงหมวดหมู่ขยะและราคากลางอ้างอิงประจำวัน [29]
- [SC-04] ยืนยันตัวตนซาเล้งและผู้ขายผ่าน Thai-ID / DBD-ID [29]

Non-goals (R1) (จาก Out Scope ของ Group2.pdf):
1. [SC-06] ยังไม่ทำระบบรองรับผู้ใช้งานแบบนิติบุคคล (เน้นครัวเรือนและซาเล้งบุคคลธรรมดาก่อน) [30]
2. [SC-07] ไม่ครอบคลุมระบบโลจิสติกส์ขนส่งขนาดใหญ่ระดับโรงงานอุตสาหกรรม [30]
3. [SC-08] ยังไม่ทำระบบคัดแยกประเภทขยะอัตโนมัติด้วย AI/Hardware (มีความซับซ้อนสูง) [30]

## 3. Actors & Context
Primary Actor: ซาเล้ง (ผู้รับซื้อของเก่า/คนขับ - กลุ่ม 2) [18, 31]
Supporting Actors: ผู้ขายของเก่า (ครัวเรือน/Gen Z), ร้านรับซื้อของเก่า (B2B/ผู้บริหารแพลตฟอร์ม), Maps/GPS API, Thai-ID/DBD API [17, 19, 31] -> ดู MD-CTX-04

## 5. Behaviour
- Use case: UC-04 (รับงานตามเส้นทาง - Level: User Goal) | Main Path 7 ขั้น | Extensions E1 (GPS หลุด), E2 (งานถูกรับไปก่อนหน้า), E3 (Maps API Timeout)
- Business rules: BR-02 (คำขอหนึ่งรายการมีซาเล้งรับผิดชอบได้เพียงคนเดียวเท่านั้น) [15, 44]
- Glossary: ใช้ชื่อสถานะคำขอตาม glossary.md ("รอผู้รับงาน", "มีผู้รับงานแล้ว", "เสร็จสิ้น")

## 6. Acceptance Criteria -> features/route.feature
AC-04-01 ถึง AC-04-08 ครอบคลุม Main Path (การค้นหาและรับงาน), Concurrent Accept (BR-02) และ NFRs (Response Time <= 3s, Accuracy <= 15%)

## 8. Constraints
REQ-CON-002 ข้อจำกัด Quota/Rate Limit ในการเรียกใช้ Maps API External | REQ-CON-003 ยานพาหนะซาเล้งมีข้อจำกัดน้ำหนักบรรทุก [18]

ข้อจำกัดด้านเทคโนโลยีที่ทีมเลือก: Frontend ใช้ React + Vite + Tailwind CSS, Backend ใช้ FastAPI, ฐานข้อมูลใช้ PostgreSQL โดยเลือกตามความเหมาะสมกับฟีเจอร์และโครงสร้างที่ต้องรองรับ Maps/GPS, Verification, และการจัดการงานตามเส้นทาง
